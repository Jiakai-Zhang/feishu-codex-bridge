# Feishu Codex Bridge v0.4.0-macos-rc.1

`v0.4.0-macos-rc.1` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 macOS 测试版本。它以 `v0.3.2-macos-rc.12` 的 Keychain、launchd Desktop relay、原生附件、临时 Chat 和事务升级为 macOS 基础，同步 `v0.4.0-windows-rc.1` 的共享多用户 Session 访问模型。

它仍依赖实验性 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。

## 相比 macOS rc.12

### 多用户 Project 与 Session 权限

- Bridge Owner 可在本机交互运行 `./setup-project-root.sh`，设置唯一 Project 根目录和 Owner 个人一级目录。绝对路径只经 stdin 进入本机私有状态，不进入命令参数、Bot 回复、仓库或日志。
- Owner 通过 `/members add <目录名> @成员` 显式登记用户。每名成员的目录不可自动重分配；新目录必须不存在或为空。
- Owner 的 `/add` 只显示 Owner 目录与旧的未归属任务；普通成员只显示自己目录内的 Project/Session，并可在个人目录内新建 Project 和任务。
- 每个 Session 仍只有一个 owner 和一个规范绑定群。把已登记成员加入群即共享该 Session，但不会分享 Project 列表或目录权限。
- 多人群只接受 `@Bot`、回复 Bot 或斜杠命令；普通 Prompt 固定 queue，显式 `/steer` 才能调整活动 Turn。最终回答只提醒当前 Turn 的初始发起者，公开进度不提醒任何人。
- 附件草稿按 Session 和发送者隔离。未登记/已停用成员、第三方 Bot、Session owner 缺席或无法完整核验群成员时，敏感内容收发 fail closed。

### macOS 平台层

- 新增 `setup-project-root.sh`，统一经由 `macos-node.sh` 和 macOS admin CLI 调用共享应用层；脚本拒绝路径参数与非交互式输入。
- Bot 中 Project 根目录缺失的安全提示同时标明 macOS `.sh` 与 Windows `.ps1` 入口，不再在 macOS 上只误报 Windows 脚本，也不把操作系统判断渗入共享领域层。
- macOS updater 备份与回滚 `session-relay-access.json`，保留 Project 根目录、成员和 Bridge 创建的 Project 状态；Keychain Secret 仍留在原安全存储中，不重新索取。
- 新安装 Prompt 锁定到本 tag。单用户默认保持 Owner-only；只在用户明确要求同机多用户时才执行 Project 根目录设置，不延长普通安装流程。

## 与 Windows v0.4 的边界

共享的 `SessionAccessStore`、目录范围、`/members`、多人群命令权限、附件草稿隔离和 fail-closed 校验相同。平台运行层不混用：macOS 继续使用 Keychain、Bash 入口和当前用户 LaunchAgent；Windows 继续使用 DPAPI、PowerShell 和 Scheduled Task。Windows v0.4 的 Desktop 代理事务升级不会被移植到 macOS；macOS 沿用已验证的 launchd relay 代理重配置与回滚逻辑。

## 安装与升级

全新安装使用本 tag 中的 [macOS 安装 Prompt](../INSTALL_MACOS_PROMPT.md)。

从以私有仓库为 `origin` 的 rc.12 升级，必须先完全退出 ChatGPT/Codex Desktop，再从独立 Terminal 运行：

```bash
./update.sh --version v0.4.0-macos-rc.1
```

现有安装若保留公开 `origin`，并已配置精确的私有镜像远端，使用：

```bash
git remote get-url private
./update.sh --version v0.4.0-macos-rc.1 --remote private
```

升级器不会创建或改写 remote，也不会执行 `reset`、`clean` 或 `stash`。工作树不干净、Desktop 未完全退出、当前 Codex 任务仍使用共享 App Server、私有远端不匹配或目标 tag 不存在时都会在改变 checkout 前停止。

## 验证

发布提交必须在 Windows 与 macOS CI 都通过：

```bash
npm ci
npm run check
```

真实 macOS 候选版验收还必须覆盖：精确 tag、Keychain Secret、Channel connected、App Server/relay/watchdog、Desktop attachment、飞书与 Desktop 双向文本/附件，以及开启多用户时的 Owner/成员 `/add` 范围、成员 Project 创建、共享 Session、多人群 queue/steer、附件草稿隔离与 fail-closed。

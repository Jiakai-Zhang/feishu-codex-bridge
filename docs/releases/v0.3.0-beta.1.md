# v0.3.0-beta.1 — 最终提醒、Desktop 自恢复与原生附件

这是 Windows / Codex 专用 Session Relay 的第三个公开测试版，重点解决最终结果提醒、Windows 重启后的 Desktop 可用性，以及 Codex 本地附件在飞书中的交付。

## 最终回答提醒

- 新增 `/settings mention on|off`，按绑定 Session 控制最终回答是否 `@owner`。
- Bot 私聊中的同一命令设置后续新绑定的默认值；修改全局默认不会追改已有绑定。
- 新安装和旧设置中缺少该字段的绑定默认开启提醒。
- 只有 Turn 最终回复、Desktop 主动同步的最终回答和 Goal 最终结果会提醒；公开进度与附件消息始终不会 `@`。

## Desktop relay fail-open 恢复

- App Server 启动被拆分为独立、串行且带进程与回环端口校验的 `start-app-server.ps1`。
- 新安装不再提前设置 `CODEX_APP_SERVER_WS_URL`。`configure-codex-desktop-relay.ps1` 只有在共享 App Server 已验证、当前用户登录恢复任务已安装后，才最后写入 Desktop relay pointer。
- 登录任务会先恢复共享 App Server，再尝试恢复 Bridge；Bridge 恢复失败不会影响 Desktop 使用 App Server。
- 如果安装目录移动、目标 release 缺少启动脚本或 App Server 无法恢复，稳定 bootstrap 会移除 Bridge 自己设置的 pointer，让 Codex Desktop 回退到内置 App Server，避免连接拒绝导致主界面无法启动。
- 从 v0.2 升级时，已有同地址 pointer 会自动迁移到 fail-open 登录恢复；迁移失败会安全撤销 pointer，而不是保留不可用依赖。
- `doctor.ps1 -RequireDesktopRelay` 会检查 pointer、登录恢复任务与共享监听器。

## 飞书群内原生附件

- 最终回答中的本地图片不超过 10 MiB 时继续内嵌显示。
- 图片超过内嵌上限、内嵌上传失败，或属于其他本地附件时，只要不超过 30 MiB，就在最终回答后按顺序发送为群内原生附件。
- Markdown 本地文件链接和 `::visualize` 指向的本地 HTML 会转换为附件；飞书消息不会暴露本机绝对路径。
- 最终回答与附件共同进入持久发件箱。附件依赖最终消息成功后再投递，上传后的 `file_key` 会在重试前持久化，发送失败不会重新运行 Codex。
- 空文件、符号链接、排队后发生变化的文件会拒绝发送；超过 30 MiB 时只显示安全提示，原文件仍留在 Codex 任务中。

## 升级已有安装

已有 `v0.2.0-beta.1` 或更高版本时，可以把下面整段发给 Codex：

```text
请按照 https://github.com/ninmon/feishu-codex-bridge/releases/tag/v0.3.0-beta.1 中的 AGENTS.md 和 docs/INSTALL_AGENT.md，把这台 Windows 电脑上已有的 Feishu Codex Bridge 安全升级到 v0.3.0-beta.1。先只读检查现有安装目录、origin、精确 tag、git status、Bridge 实时状态和 doctor；必须使用仓库自带的 update.ps1 -Version v0.3.0-beta.1。保留现有 bridge.config.json、DPAPI App Secret、群绑定、Session 设置、队列、输入账本和投递状态，不要重新索取 App Secret。若工作树不干净则停止并告诉我，不得 reset、clean、stash 或覆盖改动。升级完成后核对精确 tag，运行 status-bridge.ps1 和 doctor.ps1 -RequireRunning -RequireDesktopRelay；除非检查明确要求，不要重启 Codex Desktop 或 Windows。
```

也可以在现有安装目录中直接执行：

```powershell
.\update.ps1 -Version v0.3.0-beta.1
```

升级器继续保留本地配置、DPAPI 密文、绑定、Session 设置、队列、输入账本和投递状态，并在失败时自动恢复原 release。已经启用 Desktop relay 的 v0.2 安装会在升级过程中迁移登录恢复配置；正常情况下无需仅因代码升级而重启 Codex Desktop。

## 全新安装

把下面整段发到一个新的 Codex 任务：

```text
请按照 https://github.com/ninmon/feishu-codex-bridge/releases/tag/v0.3.0-beta.1 中的 AGENTS.md 和 docs/INSTALL_AGENT.md，在这台 Windows 电脑安装并部署 Codex Session Relay。先做只读预检；需要安装系统依赖、创建或修改飞书应用、浏览器授权、管理员审批、输入 App Secret、重启 Codex Desktop 时先说明并等我操作。不得在聊天、日志或仓库中输出 App Secret、token 或账户/会话标识。完成后运行 doctor，并实际验证飞书和 Desktop 双向消息。
```

人工安装请使用 [Windows 完整安装指南](https://github.com/ninmon/feishu-codex-bridge/blob/v0.3.0-beta.1/docs/INSTALL.md)，并在 Bridge 连接后显式运行 `configure-codex-desktop-relay.ps1` 与 `doctor.ps1 -RequireRunning -RequireDesktopRelay`。

## 验证

- Node 全量测试：234/234 通过。
- Windows 安装与升级冒烟测试通过。
- PowerShell 发布脚本语法检查和 `git diff --check` 通过。
- 本机严格 Doctor 通过；受监督 Bridge 以一个 supervisor、一个 relay 连接并订阅两个绑定任务。

## Beta 限制

- 仅支持 Windows 与 Codex Desktop。
- 依赖 Codex App Server 的实验性 WebSocket 接口；Codex 更新后应重新运行严格 Doctor。
- 飞书单文件上限为 30 MiB；更大的文件继续保留在 Codex 任务中。
- 当前尚未把 Project Agent/多人协作实现纳入稳定发布合同。

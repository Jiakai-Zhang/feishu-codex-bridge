# v0.3.2-windows-rc.1

Windows 安装流程对齐 `v0.3.2-macos-rc.11` 的新机引导与浏览器备用机制，保留 Windows 原有 DPAPI、Scheduled Task watchdog、配置格式与更新回滚契约。

## 变更

- 新增 `docs/INSTALL_WINDOWS_PROMPT.md`；README 只需给 Codex 一个固定版本协议链接。
- 新应用展示名称必须与 `[Environment]::MachineName` 完全一致。
- `setup-channel-secret.ps1` 可以在 `bridge.config.json` 生成前使用 DPAPI 保存 Secret。
- 新增 `configure-feishu-app.ps1` 和 `verify-feishu-app.ps1`；Windows 也通过飞书官方模板一次确认 11 项权限与 `im.message.receive_v1`，不再逐页重复设置默认 Bot/长连接/消息事件。
- 应用模板脚本在尝试打开浏览器前，先输出一个最多两分钟有效、不含 App ID 的本机 loopback 备用 URL；自动打开失败后链接仍可使用。
- Lark CLI 应用创建和 OAuth 流程始终向用户交付当次 verification URL，不输出 device code、原始 JSON 或应用/用户身份数据。
- Windows 飞书 CLI、安装器和 Doctor 移除继承的 HTTP/HTTPS/ALL proxy 变量，避免 Desktop 代理造成身份或事件校验假阴性。
- 新增 `launch-codex-desktop-with-relay.ps1`。不带代理参数时默认直连；只有用户明确提供无认证、带端口的 loopback URL 时才用 `-Proxy`。
- 隔离代理需要可直接启动的 Win32 Desktop；只有 packaged Desktop 时代理启动安全停止，不修改系统或用户全局代理。
- 代理只应用到 Codex Desktop 和共享 App Server。网络模式变化时，脚本只重启由本安装验证拥有的 App Server，重新注册 watchdog，并等待新鲜 heartbeat。
- watchdog 重新注册最多执行两次；每次都等待旧任务停止、同一 activation 的 `ready` heartbeat，并再次确认 Scheduled Task 仍保持运行。
- 初次绑定改为直接使用 `$feishu-session-bind`，不再要求用户先创建 Bot 私聊或发送 `/add`。
- 从尚无 Desktop 网络模式记录的旧 Windows 版本升级后，需要明确选择直连或本机代理，再通过新启动器完整重启 Desktop。

## 验收要求

```powershell
npm ci
npm run check
.\install-smoke.ps1
.\doctor.ps1 -RequireRunning -RequireDesktopRelay
```

PowerShell smoke 和严格 Doctor 需要在 Windows 10/11 上运行。正式发布还必须完成真实飞书双向消息、入站图片/文件和出站原生附件验收。

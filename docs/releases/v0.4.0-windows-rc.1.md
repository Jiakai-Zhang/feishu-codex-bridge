# Feishu Codex Bridge v0.4.0-windows-rc.1

`v0.4.0-windows-rc.1` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 Windows-only 测试版本。它在 `v0.3.2-windows-rc.4` 与 macOS rc.12 的共享 Session Relay 基线上，加入可选多用户 Project/Session 权限模型和保留 Desktop 网络状态的事务升级。

它仍依赖实验性的 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。

## 主要更新

- Bridge Owner 可在主机交互设置唯一默认 Project 根目录和自己的个人目录；普通成员各自拥有一个不可自动重分配的目录。
- Owner 的 `/add` 只显示自己的 Project/Session 与旧的未归属任务；普通成员只显示自己目录及自己拥有的 Session，并可在个人目录内创建 Project 和任务。
- 一个 Session 只有一个 owner 和一个规范绑定群；把已登记 Bridge 成员加入群即可共享 Session，不会共享 Project 列表或目录权限。
- 多人群普通 Prompt 必须明确 `@Bot`、回复 Bot 或使用命令；普通输入固定 queue，`/steer` 才调整活动 Turn。最终回答只提醒初始 Turn 发起者，公开进度不提醒。
- 附件草稿按 Session 与发送者隔离；未登记或停用成员、异常 Bot/群成员结构会安全拒绝 Session 内容收发。
- Windows updater 会锁定当前 Desktop 直连/本地代理模式、App Server 进程记录、relay state 和 bootstrap；目标安装、启动或 Doctor 失败时恢复原提交与本机状态，不静默改成直连，也不停止用户自建 guardian。
- Windows `update.ps1` 新增 `-Remote private`，macOS updater 同步支持 `--remote private`；只接受名称 `origin`/`private` 和精确维护仓库 URL，不改写 `origin`。

## macOS 边界

不要在 macOS 安装这个 tag。`v0.3.2-macos-rc.12` 不包含本版本新增的 `SessionAccessStore`、成员个人目录、多人群 Session 权限或 Windows 代理事务升级；本版本也尚未提供 macOS `setup-project-root.sh` 和真实多用户 Mac 验收。macOS 用户继续使用 rc.12，等待单独的 macOS v0.4 候选版。

## 从已经支持 `-Remote` 的版本升级

安装目录必须已有下列精确 remote：

```powershell
git remote get-url private
.\update.ps1 -Version v0.4.0-windows-rc.1 -Remote private
```

远端必须是 `https://github.com/ninmon/feishu-codex-bridge-private.git`（或该仓库的受支持 SSH 形式）。升级器不会创建或修改 remote。

## 从公开 rc.4 或更早版本首次进入私有更新通道

旧 updater 尚无 `-Remote` 参数。先完全阅读下方 Agent Prompt；人工执行时，在现有安装目录使用本机已认证 Git 凭据获取精确 tag，并从该 tag 提取目标 updater：

```powershell
$version = 'v0.4.0-windows-rc.1'
$privateUrl = 'https://github.com/ninmon/feishu-codex-bridge-private.git'
$existingPrivate = (& git remote get-url private 2>$null | Out-String).Trim()
if ($LASTEXITCODE -eq 0) {
    if ($existingPrivate -ne $privateUrl) { throw 'The existing private remote has an unexpected URL.' }
} else {
    git remote add private $privateUrl
    if ($LASTEXITCODE -ne 0) { throw 'Could not add the private release remote.' }
}
& git ls-remote --exit-code --tags private "refs/tags/$version" | Out-Null
if ($LASTEXITCODE -ne 0) { throw 'The private release tag is unavailable to this Git identity.' }
git fetch private "refs/tags/${version}:refs/tags/${version}"
if ($LASTEXITCODE -ne 0) { throw 'Could not fetch the exact private release tag.' }
$updater = Join-Path ([IO.Path]::GetTempPath()) "feishu-codex-bridge-$version-update.ps1"
git show "${version}:update.ps1" | Set-Content -LiteralPath $updater -Encoding UTF8
if ($LASTEXITCODE -ne 0) { throw 'Could not extract the updater from the exact tag.' }
& $updater -InstallRoot (Get-Location).Path -Version $version -Remote private
```

这段引导只增加一个精确私有 remote 和本地 tag，不修改工作树或 `origin`。如果 `git status --short` 非空、私有访问失败或现有同名 remote 不匹配，必须停止，不得 reset、clean、stash 或覆盖。

## 可复制的升级 Agent Prompt

```text
请把这台 Windows 电脑上已有的 Feishu Codex Bridge 安全升级到私有测试 tag v0.4.0-windows-rc.1。运行任何命令前先要求我确认当前 Codex 对话已设为 Full access，然后读取私有仓库 ninmon/feishu-codex-bridge-private 中该 tag 的 AGENTS.md、docs/INSTALL_AGENT.md 和 Release Note。

先只读检查操作系统、安装目录、GitHub CLI 登录和私有仓库访问、所有 Git remote、当前精确 tag、git status（包括未跟踪文件）、Bridge、Desktop relay 保存的直连/代理模式、App Server PID/进程记录及自建 watchdog/guardian。不要输出 Token、配置、身份标识或本机任务路径。

工作树不干净、private remote 指向其他 URL、tag 不存在、网络模式无法证明或 App Server 记录不一致时，必须在停止服务或改变 checkout 前停止。若 private remote 不存在，可添加精确 URL https://github.com/ninmon/feishu-codex-bridge-private.git；不得改写 origin。

若现有 update.ps1 支持 Remote 参数，运行 .\update.ps1 -Version v0.4.0-windows-rc.1 -Remote private。否则严格使用 Release Note 中“首次进入私有更新通道”的固定 tag 引导，从该 tag 提取临时 updater，再以 -InstallRoot 当前安装目录、-Version v0.4.0-windows-rc.1、-Remote private 执行。不得使用 main 或手工 checkout。

保留 bridge.config.json、DPAPI Secret、绑定、成员/Project 状态、Session 设置、队列、账本、附件缓存、投递状态、relay state、bootstrap 和原代理模式；不得停止或删除自建守护。完成后核对精确 tag，运行 status-bridge.ps1 与 doctor.ps1 -RequireRunning -RequireDesktopRelay。除非检查明确要求，不要重启 Codex Desktop。该 tag 是 Windows-only，不得安装到 macOS。
```

## 验证

发布前必须通过：

```powershell
npm run check
.\update-smoke.ps1
```

真实安装升级后还需验证精确 tag、Bridge connected、Desktop relay/watchdog、原代理模式、Owner `/add`、成员范围隔离、多人群 queue/steer、附件草稿隔离和最终发起者提醒。

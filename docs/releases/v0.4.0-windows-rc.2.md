# Feishu Codex Bridge v0.4.0-windows-rc.2

`v0.4.0-windows-rc.2` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 Windows-only 多用户测试版本。它以 `v0.4.0-windows-rc.1` 为基线，同步已经在共享 Session Relay 中验证的成员 onboarding、任务创建、用户名片登记和 Session 权限控制。

它仍依赖实验性的 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。公开 Windows 固定安装版仍为 `v0.3.2-windows-rc.4`；本 tag 是需要私有仓库访问权的 v0.4 测试通道。

## 相比 rc.1

### 多用户 onboarding 与任务创建

- Owner 登记成员后，Bot 会主动向该成员发送私聊欢迎消息并提示 `/add`；发送失败不会回滚已经保存的成员状态，Owner 会收到核对应用可用范围和手工搜索 Bot 的安全兜底。
- `/add` 选择任意已有 Project 后均可继续“新建任务”，不再只允许空 Project 创建第一个 Session；新 Session 创建后立即建立专属绑定群。
- Owner 可在 Bot 私聊或已有绑定群发送飞书用户名片，再按提示回复一级目录名完成成员登记；原有 `/members add <目录名> @成员` 继续兼容。

### Session 权限远程控制

- 新增 `/permissions`，显示当前 Session 的实际权限及其来源。
- Session owner 可设置 `inherit`、`read-only`、`workspace-write` 或 `danger-full-access`。普通成员、当前 Turn 发起者和 Bridge Owner 都不能修改不属于自己的 Session。
- 权限覆盖持久保存在 Session 设置中，只作用于之后由 Bridge 启动的新 Turn；活动 Turn、运行中的 Goal、其他 Session、Bridge 全局配置和 Desktop 代理都不会被修改。
- 完全访问必须在 5 分钟内通过 `/permissions confirm` 二次确认；确认绑定当前 Session、发起人和飞书会话，不能跨群复用。共享群会明确提示其他已授权成员之后提交的 Prompt 也使用同一权限边界。
- `/permissions cancel` 可取消待确认请求；`/settings reset` 不会隐式改变权限。

### 兼容性与 Windows 边界

- Session 设置持久化格式升级到 schema v4；旧记录缺少权限字段时安全迁移为 `inherit`，继续使用 Bridge 主机原有 `sandboxMode`。
- Bridge 每次启动新 Turn 都显式传递对应 `sandboxPolicy`；启动或恢复 Goal 前也会先恢复保存的 Session 权限。
- 完全访问警告使用跨平台“系统凭据存储”表述，覆盖 Windows DPAPI 与 macOS Keychain，不再向 Windows 用户显示仅属于 macOS 的术语。
- DPAPI Secret、Scheduled Task watchdog、Desktop relay、Win32/packaged Desktop 边界、直连/本机代理选择和事务升级行为没有变化。
- 升级器保留配置、DPAPI 密文、绑定、成员/Project 状态、Session 设置与权限覆盖、队列、账本、附件缓存、投递状态、relay state、bootstrap 和原代理模式；不会停止或删除用户自建 guardian。

## 从私有 rc.1 升级

已配置精确 `private` 远端的安装运行：

```powershell
.\update.ps1 -Version v0.4.0-windows-rc.2 -Remote private
```

升级前必须只读确认工作树干净、远端精确匹配私有镜像、保存的 Desktop 网络模式与活动 App Server 记录一致。不得使用 `main`、手工 checkout、`reset`、`clean` 或 `stash` 代替事务升级。

## 从公开 rc.4 首次进入私有通道

公开 rc.4 的旧 updater 尚无 `-Remote` 参数。必须先用本机已认证的 GitHub CLI/Git 凭据证明私有仓库访问，并完整读取本 release 中的 `AGENTS.md`、`docs/INSTALL_AGENT.md` 与本文件；然后在现有安装目录运行：

```powershell
$version = 'v0.4.0-windows-rc.2'
$privateUrl = 'https://github.com/ninmon/feishu-codex-bridge-private.git'
$existingPrivate = (& git remote get-url private 2>$null | Out-String).Trim()
if ($LASTEXITCODE -eq 0) {
    if ($existingPrivate -ne $privateUrl) { throw 'The existing private remote has an unexpected URL.' }
} else {
    git remote add private $privateUrl
    if ($LASTEXITCODE -ne 0) { throw 'Could not add the private release remote.' }
}
& git ls-remote --exit-code --tags private "refs/tags/$version" | Out-Null
if ($LASTEXITCODE -ne 0) { throw 'The private release tag is unavailable to this Git identity.' }
git fetch private "refs/tags/${version}:refs/tags/${version}"
if ($LASTEXITCODE -ne 0) { throw 'Could not fetch the exact private release tag.' }
$updater = Join-Path ([IO.Path]::GetTempPath()) "feishu-codex-bridge-$version-update.ps1"
git show "${version}:update.ps1" | Set-Content -LiteralPath $updater -Encoding UTF8
if ($LASTEXITCODE -ne 0) { throw 'Could not extract the updater from the exact tag.' }
& $updater -InstallRoot (Get-Location).Path -Version $version -Remote private
```

这段引导只增加精确的 `private` remote 与目标 tag，并从目标 tag 运行事务升级器；不得把 GitHub Token 放入 URL、参数或聊天，不得改写 `origin`，也不得在工作树不干净时继续。

可直接把仓库中的 [Windows 私有升级 Prompt](../INSTALL_AGENT_PROMPT.md#windows-从私有镜像升级到测试版) 交给目标 Windows 上的 Codex 执行。

## 验证

发布前要求：

```powershell
npm run check
.\update-smoke.ps1
```

macOS 本地 `npm run check` 结果为 383 项通过、1 项仅限 Windows 的 updater smoke 按预期跳过、0 失败。Windows GitHub CI 必须另外实际执行该 PowerShell updater smoke。真实 Windows 验收还应覆盖精确 tag、Bridge connected、Desktop relay/watchdog、原代理模式、成员主动私聊、用户名片登记、非空 Project 新建 Session、owner 权限查看与切换、完全访问二次确认、共享群警告，以及忙碌 Session 拒绝修改权限。

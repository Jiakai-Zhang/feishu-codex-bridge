# v0.3.2-macos-rc.9

`v0.3.2-macos-rc.9` 修复 rc.8 真实安装测试中发现的两项 macOS 代理切换问题。它继续使用实验性的 Codex App Server WebSocket listener，不是稳定 release。

## 修复

- launchd 卸载 relay watchdog 后会等待旧注册真正消失，避免紧接着的 bootstrap 误判旧 job 仍已加载。
- relay 激活会执行 `bootstrap` 和 `kickstart`，要求 LaunchAgent 保持加载、pointer 正确且新 activation 发布新鲜 `ready` 心跳；首次注册未驻留时自动完整重试一次。
- 两轮 watchdog 注册均失败时，Desktop 启动器会停止，不会在 relay 未就绪时继续打开 Desktop。
- `lark-cli.sh`、`verify-feishu-app.sh`、安装器与 Doctor 使用的飞书 CLI 子进程会移除继承的 HTTP/HTTPS/ALL proxy 和 NO_PROXY 变量，使飞书身份、OAuth scope 与事件校验保持直连。
- Desktop 与共享 Codex App Server 的已保存代理选择不受飞书直连校验影响。

## 兼容性

- 不改变 `bridge.config.json`、Keychain 凭据、绑定、队列、附件缓存或 Desktop 代理持久化格式。
- 从 rc.8 更新时不需要重新输入 App Secret、重新 OAuth 或重建飞书应用。

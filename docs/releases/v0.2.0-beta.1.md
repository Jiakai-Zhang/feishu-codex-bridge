# v0.2.0-beta.1 — Session 设置、公开进度与安全升级

这是 Windows / Codex 专用 Session Relay 的第二个公开测试版。

## 新功能

- 新增群内 `/settings`：每个绑定 Session 可独立选择普通消息默认使用 `steer` 或 `queue`，并开启或关闭公开进度。
- 新增 Bot 私聊全局 `/settings`：只作为以后新建绑定的默认快照，不追改已有 Session。
- 全新安装默认采用 `queue + 公开进度开启`；旧部署中没有设置记录的已有群仍保持 `steer + 公开进度关闭`，避免升级改变既有行为。
- 公开进度只转发 App Server 明确标记为 commentary 的阶段说明，按 `Codex 公开进度 #1/#2…` 编号。隐藏思维链、reasoning、raw reasoning、工具原始输出始终不会发到飞书。
- Bridge 重连后，活动 Turn 的公开进度序号可从当前快照继续；最终回答仍使用持久发件箱和确定性投递 ID。
- 新绑定欢迎消息会显示该 Session 创建时复制到的输入模式与公开进度设置。

## 升级机制

- 新增 `update.ps1 -Version <tag>`：只允许固定语义版本 tag、已批准仓库 origin 和干净工作树。
- 升级前优雅停止 Bridge，并在本机运行目录备份本地配置、DPAPI 密文、Session 设置、队列、输入账本和投递状态。
- 切换目标 tag 后运行锁定的 `npm ci`、保留配置的安装脚本和 `doctor.ps1`；原本运行的 Bridge 会自动恢复运行。
- 依赖安装、安装脚本、启动或健康检查失败时，自动切回原提交、恢复本地状态并重新启动原版本；升级器不执行 `git reset` 或 `git clean`。
- 新增隔离临时仓库冒烟测试，覆盖成功升级、状态保留和故障自动回滚。

## 从 v0.1.0-beta.1 升级

旧版尚未内置升级器。请在旧安装目录按照 [`docs/INSTALL.md`](../INSTALL.md#更新) 的固定-tag 引导，从本 release 下载 `update.ps1` 到系统临时目录后执行。升级成功后核对精确 tag、Bridge connected 状态和 `doctor.ps1 -RequireRunning`。

本版本的 Bridge 代码升级不要求强制重启 Codex Desktop；如果共享 App Server 地址或 Desktop 环境检查发生变化，仍应按检查提示完整重启。

## 验证

- Node 测试与 Windows 升级冒烟测试全部通过。
- 发布前再次核对本机 Bridge、supervisor、共享 App Server 和绑定任务订阅状态。

## Beta 限制

- 仅支持 Windows 与 Codex Desktop。
- 依赖 Codex App Server 的实验性 WebSocket 接口；Codex 更新后应重新运行 `doctor.ps1`。
- 当前启动器不是 Windows Service；Windows 注销或重启后仍需再次运行 `start-bridge.ps1`。
- 仓库保留的 Project Agent/多人协作实现不属于本版本的稳定发布合同。

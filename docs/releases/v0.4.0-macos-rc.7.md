# v0.4.0-macos-rc.7

macOS 多用户候选版。此版本以 `v0.4.0-windows-rc.5` 已验证的升级生命周期为参考，补齐 macOS 独立前台升级、Desktop 精确身份和同版本自愈；不改变飞书命令、权限、配置 schema、Keychain Secret、绑定或 Session access 格式。

## 相对 macOS rc.6

- 新增 `src/runtime/platform/macos/update-with-desktop-restart.sh`，并由 `update.sh --foreground` 路由。入口从精确目标 tag 提取目标 runtime，在可见 Terminal 中完成预检、等待用户 `⌘Q`、事务升级、按原网络模式自动重开 Desktop 和最终 Doctor，不依赖发起升级的 Codex 进程继续存活。
- 前台任务只有在状态明确进入 `waiting-for-desktop-exit` 后才输出 `Foreground upgrade is ready`；调用端不能因 Terminal 窗口出现就假定准备成功。
- 更新前验证严格 Doctor、完整未跟踪文件、精确 tag、relay heartbeat、持久网络选择和活动 App Server 环境。更新后在重开 Desktop 前后各执行严格 Doctor，并复核精确提交和干净工作树。
- Desktop App 不再只依赖 `/Applications` 中的硬编码名称。运行时通过 Spotlight/fallback 候选、`CFBundleIdentifier`、OpenAI Team ID `2DC432GLL2`、codesign 严格验证和规范 `Contents/MacOS` 可执行路径共同锁定身份，同时支持用户级 `~/Applications` 安装。
- macOS 等待已经锁定的 Desktop 主进程及其内嵌 App Server 自然退出，不复制 Windows 的窗口句柄与残留 package 进程强制结束逻辑，也不按宽泛进程名杀进程。
- 启动器增加内部 `--preserve-network` 模式，从 relay 私有状态读取原直连/本地代理选择；代理 URL 不需要写入新的前台升级启动参数。活动 App Server 与保存选择不一致时，在改变 checkout 前停止。
- 底层 updater 增加只读 `--preflight-only` 契约，脏工作树检查覆盖全部未跟踪文件。relay 已启用时，`shouldStart` 会包含 relay 状态；因此同一 tag 下 Bridge 意外停止也能通过 updater 恢复 Bridge、relay 与 watchdog。
- Desktop 已退出后的失败会先依赖底层事务回滚，再尝试按原网络模式重新打开 Desktop；失败窗口保持可见，不会误报成功。

## 与 Windows rc.5 的平台差异

- Windows 使用当前用户、Interactive、Limited 的一次性 Scheduled Task；macOS 使用当前用户的可见 Terminal `.command`，不创建常驻升级 LaunchAgent。
- Windows 在可见窗口关闭后只结束已验证为同一可执行路径的残留 package 进程；macOS 明确要求 `⌘Q` 并等待同一签名 Bundle 自然退出。
- Windows 从 AppX manifest 解析 packaged executable；macOS 从 Info.plist、codesign Team ID 和规范 Bundle 路径解析。
- 两个平台都使用目标 tag 自带的 updater、保留原网络模式、执行事务回滚与重开前后严格 Doctor。

## 更新

正常 Codex 升级必须完整读取 `docs/UPGRADE_MACOS_PROMPT.md`，从此精确 tag 提取并启动目标版本的 `src/runtime/platform/macos/update-with-desktop-restart.sh`。用户只在入口明确准备完成后按 `⌘Q`，无需执行命令或手工重开 Desktop。

底层人工恢复入口仍为：

```bash
./update.sh --version v0.4.0-macos-rc.7 --remote private
```

它只可在 Desktop 已完全退出的独立 Terminal 中使用。不得在 macOS 上运行 Windows updater。

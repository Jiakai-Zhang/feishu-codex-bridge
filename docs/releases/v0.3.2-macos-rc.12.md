# v0.3.2-macos-rc.12

`v0.3.2-macos-rc.12` 以 rc.11 的 macOS 安装、Keychain、代理和 Desktop relay 安全边界为基础，合入当前共享 Session Relay 基线，并补齐私有发行仓库的固定安装、更新回滚和 macOS CI。它继续使用实验性的 Codex App Server WebSocket listener，不是稳定 release。

## 相比 v0.3.2-macos-rc.11

### Session Relay 能力

- Bot 私聊和绑定群新增 `/chat [首条 Prompt]` 与 `/endchat`，临时 Chat 使用独立 Codex Session，状态、队列和回复目标可跨 Bridge 重启保存。
- Codex 输出的图片、MP4 视频和普通文件分别使用飞书原生 image、media 与 file 消息发送；POSIX 本地附件路径在 macOS 和跨平台测试中保持正确。
- 一个 Session 被 Desktop 或其他 App Server 占用时，只隔离该 Session，并在 writer 释放后按需恢复；其他绑定和 Channel 连接不再被一起阻塞。
- JSON 状态写入统一串行化，避免同一进程中的并发持久化互相覆盖。
- 流式卡片完成后会把完整最终回答再次作为最新消息发送，随后按顺序发送原生附件。

### macOS 发布与升级

- 固定安装 Prompt 改为私有仓库 `ninmon/feishu-codex-bridge-private` 和精确 tag `v0.3.2-macos-rc.12`；安装前必须确认 GitHub CLI 已登录且账号有仓库访问权。
- `update.sh` 接受受维护的私有发行仓库，同时继续接受公开 fork 与上游仓库，不放宽到其他 owner 或相似仓库名。
- 升级恢复备份加入 `session-relay-temporary-chats.json`；目标版本安装或 Doctor 失败时，会恢复升级前的临时 Chat 状态。
- GitHub Actions 同时在 `windows-latest` 与 `macos-latest` 运行完整 `npm run check`，macOS 安装 smoke 和升级回滚测试成为发布门禁。

### 保持不变

- Channel App Secret 仍只通过 `setup-channel-secret.sh` 写入当前用户 Keychain，不进入命令参数、配置、日志或 Git。
- 安装仍先要求当前 Codex 对话使用 Full access，再完成飞书浏览器认证、应用模板确认、OAuth、可能的管理员审批和 Desktop 完整重启。
- Codex 直连或本机代理仍由用户明确选择；代理只应用于 Desktop 与共享 App Server，飞书 CLI、Channel 和 watchdog 保持直连。
- 初次绑定仍使用 `$feishu-session-bind`，不要求先创建 Bot 私聊或发送 `/add`。

## 验收

发布提交在 macOS Apple Silicon 上运行：

```bash
npm ci
npm run check
```

固定 release 发布后仍需在实际安装机运行：

```bash
./doctor.sh --require-running --require-desktop-relay --require-desktop-attached
```

并完成飞书与 Desktop 双向文本、入站图片/文件、出站图片/视频/普通附件和临时 Chat 验收。

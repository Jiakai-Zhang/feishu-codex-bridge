# Feishu Codex Bridge v0.4.0-macos-rc.5

`v0.4.0-macos-rc.5` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 macOS 多用户测试版本。它以 `v0.4.0-macos-rc.4` 为基线，让 Session owner 可以从飞书查看并调整自己 Session 的持久 Codex 权限边界。

它仍依赖实验性 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。

## 相比 rc.4

### Session 权限远程控制

- 新增 `/permissions`，显示当前 Session 的实际权限及其来源。
- Session owner 可设置 `inherit`、`read-only`、`workspace-write` 或 `danger-full-access`。普通成员、当前 Turn 发起者和 Bridge Owner 都不能修改不属于自己的 Session。
- 权限覆盖持久保存在 Session 设置中，只作用于之后由 Bridge 启动的新 Turn；它不修改活动 Turn、其他 Session、Bridge 全局配置或 Desktop 代理。
- 修改时 Session 必须空闲且没有运行中的 Goal。启动或恢复 Goal 前，Bridge 也会先把保存的 Session 权限应用到 thread。
- 完全访问必须在 5 分钟内通过 `/permissions confirm` 二次确认；确认请求绑定当前 Session、发起人和飞书会话，不能跨群复用。共享群会明确提醒其他已授权成员之后提交的 Prompt 也使用同一权限边界。
- `/permissions cancel` 可取消待确认请求。`/settings reset` 只重置消息行为，不会隐式改变权限。

### 兼容性与安全迁移

- Session 设置持久化格式升级到 schema v4；旧记录没有权限字段时安全迁移为 `inherit`，继续使用 Bridge 主机原有 `sandboxMode`。
- 每次 Bridge 启动新 Turn 时都会显式传递对应 `sandboxPolicy`；`read-only` 和 `workspace-write` 保持网络关闭，工作区写入范围限定为绑定 Session 的 cwd。
- 成员目录、绑定、临时 Chat、队列、附件、投递状态、Keychain Secret、OAuth、飞书应用权限和 relay state 均不重置。
- rc.4 的用户名片登记、主动私聊 onboarding、非空 Project 新建 Session 及原有 mention 命令全部保留。

## 安装与升级

全新安装使用本 tag 中的 [macOS 安装 Prompt](../INSTALL_MACOS_PROMPT.md)。

现有安装若已配置精确的私有镜像远端，必须先完全退出 ChatGPT/Codex Desktop，再从独立 Terminal 运行：

```bash
./update.sh --version v0.4.0-macos-rc.5 --remote private
```

升级器保留 `bridge.config.json`、Keychain Secret、绑定、成员/Project 状态、Session 设置与权限覆盖、临时 Chat、队列、账本、附件缓存、投递状态、Desktop relay state 与已保存代理模式。它不会改写 `origin`，也不会执行 `reset`、`clean` 或 `stash`。

## 验证

发布前必须运行：

```bash
npm run check
```

本次本地结果为 383 项通过、1 项平台相关跳过、0 失败；macOS loopback、安装/升级回滚、relay/watchdog 与新增 Session 权限流程测试均实际执行通过。

真实 macOS 验收还应覆盖精确 tag、Bridge/Channel、App Server/relay/watchdog、Desktop attachment、原代理一致性，以及 owner 权限查看、非完全访问即时切换、完全访问二次确认、共享群警告和忙碌 Session 拒绝修改。

# Feishu Codex Bridge v0.4.0-macos-rc.6

`v0.4.0-macos-rc.6` 是私有 macOS 多用户候选版。运行时代码与 rc.5 保持兼容，本版把全新安装和固定版本升级统一为仓库内的极简入口，避免再次把长协议粘贴到 Codex 对话。

## 主要变化

- 新增 `docs/UPGRADE_MACOS_PROMPT.md`：正常健康路径由 Codex 完成预检、准备独立 Terminal、运行事务 updater 和严格 Doctor。
- 用户不再需要复制或执行 Terminal 命令；独立更新任务准备完成后，只需完全退出 Desktop、等待 Terminal 明确成功，再重新打开 Desktop。
- Full access、GitHub 私库认证、干净工作树、精确 tag、代理/App Server 一致性和自建守护边界仍是强制检查；异常时在改变安装前暂停。
- `docs/INSTALL_AGENT_PROMPT.md` 与 README 只保留固定 tag、文件名和 GitHub CLI 读取要求，完整规则继续放在版本锁定协议中。
- macOS 全新安装入口更新到本 tag；应用创建、模板权限、Secret、OAuth、网络选择、Desktop 重启、Doctor 和真实双向附件验收要求没有放宽。

## 升级

推荐把 README 中的 macOS 极简升级 Prompt 复制给当前 Mac 上的新 Codex 任务。协议内部最终使用：

```bash
./update.sh --version v0.4.0-macos-rc.6 --remote private
```

正常路径不需要用户手工运行这条命令。updater 保留 Keychain Secret、本机配置、绑定、成员/Project 状态、Session 设置与权限、队列、附件、投递状态、relay state、bootstrap 和原代理模式；失败时自动回滚。

## 验证

macOS 本地 `npm run check` 结果为 383 项通过、1 项仅限 Windows 的 updater smoke 按预期跳过、0 失败，其中包含 macOS updater 集成测试。发布前还要求 GitHub Windows/macOS 双平台 CI 全部通过。升级后必须验证精确 tag、Bridge connected、共享 App Server、watchdog、Desktop relay/attachment 和原网络模式。

# v0.4.0-macos-rc.8

macOS 多用户候选版。此版本修复 rc.7 首次真实前台升级测试暴露的恢复兼容问题，并增强安装阶段的可恢复性与安全诊断；不改变飞书命令、权限、配置 schema、Keychain Secret、绑定、成员目录或 Session access 格式。

## 相对 macOS rc.7

- 前台 runtime 不再通过当前 checkout 的 `launch-codex-desktop-with-relay.sh --preserve-network` 重开 Desktop。成功更新和失败回滚都使用目标 tag 已提取的同一前台 runtime，重新验证持久网络选择、活动 App Server、relay heartbeat、签名 Bundle 与 Desktop attachment 后直接启动。因此回滚到不认识新参数的 rc.5/rc.6 也能恢复。
- 代理选择只在权限受限的 relay state 与前台进程内存中读取和比较；不会写入 Terminal `.command`、状态摘要、聊天或仓库。打开 Desktop 时仍只接受无认证、带明确端口的 loopback URL。
- 底层安装器首次失败时进行一次幂等重试。两次都失败才进入原有事务回滚；目标安装和回滚安装共用同一策略。
- updater 会同步保留子进程的末行安全诊断，删除本机路径和飞书/Codex 身份格式后写入可见失败摘要与权限受限的前台状态。不会再只留下 `exit code 1`。
- 新增跨版本 Desktop 重开参数构造测试、代理/直连测试、一次性安装失败后重试成功测试，以及既有失败回滚与私有状态保留回归。

## 已知 rc.7 现场结果

rc.7 的事务回滚成功恢复了旧 tag、本机配置、Bridge、Channel、共享 App Server、relay watchdog 和 Desktop attachment，但恢复启动调用了旧 checkout 不支持的 `--preserve-network`，导致 Terminal 报告恢复启动失败。rc.8 删除了这项跨版本依赖。

## 更新

正常 Codex 升级必须完整读取 `docs/UPGRADE_MACOS_PROMPT.md`，从此精确 tag 提取并启动目标版本的 `src/runtime/platform/macos/update-with-desktop-restart.sh`。用户只在入口明确准备完成后按 `⌘Q`，无需执行命令或手工重开 Desktop。

底层人工恢复入口仍为：

```bash
./update.sh --version v0.4.0-macos-rc.8 --remote private
```

它只可在 Desktop 已完全退出的独立 Terminal 中使用。不得在 macOS 上运行 Windows updater。

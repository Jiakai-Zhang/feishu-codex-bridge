# Feishu Codex Bridge v0.4.0-windows-rc.4

`v0.4.0-windows-rc.4` 是私有 Windows 多用户候选版。本版不改变 Session Relay 的消息、权限或持久化语义，重点修复“从正在运行的 Codex 任务升级，退出 Desktop 后临时监控进程一并消失，因而没有自动重开”的升级生命周期问题。

## Windows 前台升级器

- 新增 `update-windows-with-desktop-restart.ps1`。它创建当前用户、Interactive、Limited、无触发器的一次性 Scheduled Task，在可见 Windows PowerShell 中独立完成升级，因此不依赖发起升级的 Desktop/Codex 进程继续存活。
- 前台窗口先从目标固定 tag 提取目标 `update.ps1`，执行 `-PreflightOnly` 和严格 Doctor，再提示用户完全退出 Desktop。
- Desktop 退出后依次执行事务升级、精确提交与干净工作树检查、严格 Doctor、按原 `-Proxy`/`-NoProxy` 模式自动重开 Desktop 和第二次严格 Doctor。
- 成功状态在本机写入后注销一次性任务；升级失败会保留前台错误，并在 Desktop 已退出时尝试用原网络模式恢复启动。
- `docs/UPGRADE_WINDOWS_PROMPT.md` 现在必须执行这个前台入口。健康路径中用户只退出 Desktop，不再手工重开，也不运行升级命令。

## 升级器与兼容性修复

- `update.ps1` 新增无写入的 `-PreflightOnly`，并修复 Windows PowerShell 5.1 通过 `-File` 调用时默认安装目录可能为空的问题。
- updater 自己生成且恰好落在 checkout 内的 `upgrade-backups/` 不再被误判为普通用户改动；其他已跟踪或未跟踪内容仍会安全拒绝。
- `doctor.ps1`、`status-bridge.ps1` 与 Desktop relay 激活器兼容 PowerShell 5.1/7 对 JSON ISO 时间戳的不同反序列化结果，避免 PowerShell 7 把正常 UTC heartbeat 误判为过期。

## 发布验收

发布前必须在 Windows PowerShell 5.1 与 PowerShell 7 完成语法检查，运行 updater 回滚 smoke、前台 Desktop 退出/代理保留/自动重开 smoke 和 `npm run check`。真实主机升级后还必须确认精确 tag、Bridge connected、共享 App Server、watchdog、Desktop relay 与升级前网络模式。

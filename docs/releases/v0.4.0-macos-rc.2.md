# Feishu Codex Bridge v0.4.0-macos-rc.2

`v0.4.0-macos-rc.2` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 macOS 多用户测试版本。它以 `v0.4.0-macos-rc.1` 为基线，改善新成员从登记到首次 `/add` 的 onboarding，不改变已有成员目录、绑定、Session 设置、队列、附件或投递状态格式。

它仍依赖实验性 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。

## 相比 rc.1

### 新成员主动私聊指引

- Owner 的 `/members add <目录名> @成员` 先持久化成员和个人目录，再由 Bot 使用飞书 `open_id` 投递一条富文本欢迎消息。消息会让 Bot 私聊出现在新成员的消息列表中，并明确提示 Bridge 重载后在该私聊发送 `/add`。
- 欢迎消息只说明个人 Project/Session 边界和共享 Session 仍需加入绑定群；消息正文不包含用户标识、应用标识、本机路径或其他本机配置。
- 飞书投递失败不会回滚已经成功登记的成员或删除目录。Owner 会收到明确兜底，提示核对应用可用范围，并让成员手动搜索 Bot 后发送 `/add`。
- 成员登记成功后仍通过 supervisor 自动重载 Bridge，使新成员进入私聊 allowlist。没有新增飞书权限；主动消息复用既有 `im:message`，目标用户仍必须处于应用可用范围。

### 安全边界不变

- `/members` 仍只有 Bridge Owner 可执行；完整成员清单仍只在 Owner 与 Bot 的私聊显示。
- `/members add/remove` 仍只在 Bot 私聊或已有绑定群处理。未绑定普通群不在 Channel 群白名单中，本版本不会为了管理成员而扩大群消息接收面。
- 普通成员仍只能在自己的 Bot 私聊使用 `/add`，且只能看到或创建个人目录内的 Project/Session；绑定群中的 `/add` 只引导回 Bot 私聊。

## 安装与升级

全新安装使用本 tag 中的 [macOS 安装 Prompt](../INSTALL_MACOS_PROMPT.md)。

现有安装若已配置精确的私有镜像远端，必须先完全退出 ChatGPT/Codex Desktop，再从独立 Terminal 运行：

```bash
./update.sh --version v0.4.0-macos-rc.2 --remote private
```

升级器保留 `bridge.config.json`、Keychain Secret、绑定、成员/Project 状态、Session 设置、临时 Chat、队列、账本、附件缓存、投递状态、Desktop relay state 与已保存代理模式。它不会改写 `origin`，也不会执行 `reset`、`clean` 或 `stash`。

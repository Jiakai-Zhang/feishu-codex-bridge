# Feishu Codex Bridge v0.4.0-macos-rc.4

`v0.4.0-macos-rc.4` 是发布在私有镜像 `ninmon/feishu-codex-bridge-private` 的 macOS 多用户测试版本。它以 `v0.4.0-macos-rc.3` 为基线，为 Bridge Owner 增加通过飞书用户名片登记成员的两步流程，同时保留原有 mention 命令。

它仍依赖实验性 Codex App Server WebSocket listener，不是稳定 release。`package.json` 的 npm 版本不是安装版本依据，精确 Git tag 才是版本边界。

## 相比 rc.3

### 用户名片登记成员

- Owner 可在与 Bot 的私聊或已有绑定群发送一张飞书用户名片；Bot 随后询问该成员的一级目录名，Owner 回复一个安全目录名即可完成登记。
- 名片流程一次只保存一个待登记目标，15 分钟后自动失效；`/cancel` 可取消，重新发送另一张名片会替换当前选择。其他斜杠命令会退出名片流程并继续由原路由处理。
- 入站名片若已携带当前应用的 `open_id`，Bridge 直接使用；否则通过现有“获取消息”接口按 `open_id` 类型重读同一条消息。应用模板不增加通讯录权限。
- 用户标识只在内存和既有私有成员状态中使用，不写进 Bot 回复或日志。无法确认当前应用身份时安全拒绝，并提示 Owner 改用 mention 命令。
- `/members add <目录名> @成员` 与 `/members remove @成员` 保持兼容。只有 Owner 可以登记成员，入口仍限 Bot 私聊或已有绑定群；发送名片或完成登记都不会自动邀请用户进入 Session 群。
- 登记成功后沿用 rc.2 的主动 Bot 私聊 onboarding，并通过既有 Supervisor handshake 重载 Bridge。

### 兼容性

- 成员目录、绑定、Session 设置、队列、附件、投递状态和 relay state 的持久化格式没有变化。
- 飞书应用的 11 项权限和 `im.message.receive_v1` 事件模板没有变化。
- Desktop 直连/代理选择、共享 App Server、watchdog、Keychain Secret 与 OAuth 状态均不迁移、不重置。

## 安装与升级

全新安装使用本 tag 中的 [macOS 安装 Prompt](../INSTALL_MACOS_PROMPT.md)。

现有安装若已配置精确的私有镜像远端，必须先完全退出 ChatGPT/Codex Desktop，再从独立 Terminal 运行：

```bash
./update.sh --version v0.4.0-macos-rc.4 --remote private
```

升级器保留 `bridge.config.json`、Keychain Secret、绑定、成员/Project 状态、Session 设置、临时 Chat、队列、账本、附件缓存、投递状态、Desktop relay state 与已保存代理模式。它不会改写 `origin`，也不会执行 `reset`、`clean` 或 `stash`。

## 验证

发布前必须运行：

```bash
npm run check
```

本次本地结果为 374 项通过、1 项平台相关跳过、0 失败；macOS loopback、安装/升级、relay/watchdog 与新增用户名片流程测试均实际执行通过。

真实 macOS 验收还应覆盖精确 tag、Bridge/Channel、App Server/relay/watchdog、Desktop attachment、原代理一致性，以及由 Owner 发送测试用户名片、回复目录名、确认主动私聊和成员 `/add` 的完整流程。

# v0.4.0-macos-rc.9

macOS 多用户候选版。此版本修复 rc.8 第二次真实前台升级测试定位到的 Node 运行时交接问题；保留 rc.8 的跨版本 Desktop 恢复、安装重试和安全诊断，不改变飞书命令、权限、配置 schema、Keychain Secret、绑定、成员目录或 Session access 格式。

## 相对 macOS rc.8

- 目标 tag 入口已选择并验证 Node 后，前台 worker 会把自己的绝对 `process.execPath` 固定到事务环境中的 `FEISHU_CODEX_BRIDGE_NODE`。目标 `bootstrap.sh`、`install.sh` 以及失败回滚都继承同一运行时，不依赖 Desktop 退出后的独立 Terminal PATH。
- 固定值只存在于前台 worker 及其子进程环境；不会写入聊天、Terminal `.command`、Git 或新的身份配置。正常安装器仍保留现有 `bridge.config.json` 中的运行时选择。
- 入口继续通过版本检查、签名 Desktop Bundle 或受支持系统 Node 选择 worker；事务只复用已经实际启动成功的同一 Node，不接受相对路径。
- 新增 Node 环境固定的行为测试与前台编排契约断言；完整更新、一次性安装重试、失败回滚、代理/直连恢复和 Desktop attachment 回归继续通过。

## rc.8 现场结果

rc.8 已正确回滚旧 tag、恢复 Bridge、Channel、共享 App Server、relay watchdog，并通过不依赖旧 checkout 新参数的独立路径按原代理模式重开 Desktop。安全诊断随后明确指出事务失败发生在 `bootstrap.sh`：Desktop 退出后，Terminal 无法重新发现 Node.js。rc.9 直接修复这项运行时交接。

## 更新

正常 Codex 升级必须完整读取 `docs/UPGRADE_MACOS_PROMPT.md`，从此精确 tag 提取并启动目标版本的 `src/runtime/platform/macos/update-with-desktop-restart.sh`。用户只在入口明确准备完成后按 `⌘Q`，无需执行命令或手工重开 Desktop。

底层人工恢复入口仍为：

```bash
./update.sh --version v0.4.0-macos-rc.9 --remote private
```

它只可在 Desktop 已完全退出的独立 Terminal 中使用。不得在 macOS 上运行 Windows updater。
